# Kiwix/ZIM adapter assessment

Assessment ID: `PSAI107-QWEN-07-KIWIX-ADAPTER-ASSESSMENT`

This is an assessment harness, not a Kiwix/ZIM importer. It answers one bounded question:

> Could a future ZIM reader normalize its output into the existing immutable edition and read-only query receipt lifecycle without creating another state owner, receipt type, or truth authority?

The answer is `ACCEPT` only for an input-only reader whose normalized output satisfies every shared check. Missing evidence is `DEFER`; incompatible ownership, media, decompression, or authority behavior is `REJECT`.

## Preserved process context

The harness records Operating Model `1.1` and preserves `D-001` through `D-007`. It introduces no process variant and does not amend or supersede those decisions.

The implementation boundary is deliberately narrow:

- no ZIM parser, decompressor, downloader, or second importer;
- no Kiwix-specific active pointer, Accepted/LKG store, rollback state, or lifecycle;
- no Kiwix-specific query receipt;
- no network, model, execution authority, or automatic truth promotion;
- only the existing canonical edition projector, edition validator, lifecycle readback, and read-only query receipt validator are exercised.

## Requirements a future reader must meet

The assessment enumerates five requirement groups in `tests/fixtures/kiwix-zim-assessment/assessment-v1.json`.

1. Provenance: bind an immutable source URL, source SHA-256, source byte size, source path, reader/parser/decompressor versions, and the snapshot to the imported data.
2. Identity: retain project, language, canonical URL, stable title identity, page ID, and revision ID or a demonstrably equivalent history identity for every page.
3. License: verify the source license, permitted use, and compatibility with the existing canonical license enum before acceptance.
4. Attribution: retain source attribution in the edition and on every query result.
5. Immutable snapshot: record the snapshot date, require deterministic decompression, replay to the same content and edition digests, and address the accepted edition by its digest.

A future reader is compatible only when it is explicitly `INPUT_ONLY` and maps one way to:

- `chimpmaera.knowledge/mediawiki-mini-dump-edition/v1`;
- `chimpmaera.knowledge/mediawiki-readonly-query-receipt/v1`;
- the existing MediaWiki edition lifecycle and active pointer.

The reader must pass the canonical edition validator, immutable digest replay, shared lifecycle active readback, shared query receipt validation and corpus readback, complete result provenance, contradiction visibility, and no-automatic-truth checks. It does not get to define a parallel equivalent of any of those contracts.

## Reproducible fixtures

The focused test exercises two canonical imports:

- the repository's six-page synthetic mini dump, imported twice with equal content and edition digests;
- one bounded official-pilot metadata profile, imported twice through the existing canonical projector with equal digests.

The repository intentionally contains no official Wikimedia bytes. The bounded pilot case therefore uses the existing synthetic bytes as a clearly labelled test double while binding the official pilot URL, checksum, byte size, date, project, license, and attribution shape. It receives no official-content or production-compatibility credit. This keeps the test offline and prevents synthetic material from being promoted to official evidence.

Both editions are validated with the existing immutable edition contract. Query receipts are generated by the existing read-only query path and checked against their corpus. Every result is required to include the exact passage, project, page ID, revision ID, canonical URL, snapshot date, license and attribution, content digest, and edition digest.

The test also creates a second changed edition as an explicitly `UNVERIFIED` selected source. Conflicting passages remain as separate results, carry distinct edition digests, are marked `DISPUTED`, and appear in the receipt's contradiction list. Wikipedia or any other source is never promoted to automatic truth by this assessment.

## Fail-closed matrix

The required negative cases are fixture-owned and executable:

| Case | Verdict | Reason |
| --- | --- | --- |
| absent revision/history-equivalent attribution | `DEFER` | `REVISION_HISTORY_ATTRIBUTION_MISSING` |
| unverifiable source or license | `DEFER` | `SOURCE_OR_LICENSE_UNVERIFIABLE` |
| media ambiguity | `REJECT` | `MEDIA_AMBIGUITY` |
| non-deterministic decompression | `REJECT` | `NON_DETERMINISTIC_DECOMPRESSION` |
| separate active pointer | `REJECT` | `SEPARATE_ACTIVE_POINTER` |
| separate query receipt | `REJECT` | `SEPARATE_QUERY_RECEIPT` |
| claim that ZIM is automatically accepted/truth | `REJECT` | `AUTOMATIC_TRUTH_NOT_ALLOWED` |

A compatible future adapter remains input-only and must hand its normalized records to the same canonical edition, lifecycle, query, receipt, contradiction, and provenance checks. Passing this assessment does not implement or accept a ZIM adapter.

## Focused verification

```text
node --test tests/kiwix-zim-assessment.test.mjs
git diff --check origin/main...HEAD
```

The focused test is intentionally runnable without a network or a ZIM dependency. The local Node runtime may abort with exit `133`/`SIGTRAP` during V8 initialization in this environment; that is infrastructure evidence, not a product verdict. The controller should rerun the focused check with the pinned Node runtime when available.
