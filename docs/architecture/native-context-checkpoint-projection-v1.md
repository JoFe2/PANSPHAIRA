# Native operative context and checkpoint contract v1

Original607 is the additive model-free CONTEXT profile authorised by AC08.
Actual Main-model consideration is INTEGRATION612 through the authorised PAN575
route, price/currency/usage and explicit capped consent; it is not exercised or
claimed here. Worker credentials, fixture sessions and a checkpoint cursor grant
no model, audio, private-source sampling, production, business, save, send or KS
rights. PAN565/PAN567/PAN575/PAN548 real-model holds remain separate.

## Existing owners and direct use

PAN548's existing UI task/session owner and SQLite connection retain task state,
revision, boot fencing, bounded lease, runtime/model limits and cancel markers.
The signed context outbox, target evidence projections and checkpoint metadata
reference those actual rows, not a second task or policy engine. PAN546 owns
native view candidate validation; PAN597 owns Surface/Delivery and its native
source reader/DOM acknowledgement. PAN592 remains the broader multiprocess owner.

With existing protected workspace context/module views and surfaces enabled,
the existing canvas contributes “Operativer Kontext — lokaler Vertrag”. There
is no alternate HTML application or desktop client. Reviewer operations retain
the existing v1 reviewer CSRF boundary. An authenticated reader may read its own
minimised snapshot but acquires no mutation permission. CSRf recovery uses the
existing session adapter; the token is outside snapshot/payload/prompt bytes.

1. Open the registered native ERP object/context in the existing workspace.
2. Fix a Main contract snapshot. This creates an existing PAN548 checkpoint
   task, immutable source-stream/snapshot/payload/prompt bytes and PREPARED.
3. Explicitly check the fixed request bytes locally. The real protected TLS
   receiver reads their exact UTF-8 bytes and records INCLUDED_IN_PROMPT.
4. Independently check the local contract result against the fixed task set,
   native target registers, current resource versions and privacy/session epoch.
   Only then is RESULT_CHECKED/cursor advancement recorded.
5. At a TURN/TOOL boundary fix a new request. Do not mutate a live prompt.

INCLUDED_IN_PROMPT here means the model-free native request contract was
received, with observer NATIVE_HTTP_CONTRACT_NOT_MODEL_PROVIDER and model
NOT_RUN. RESULT_CHECKED is local contract validation, never semantic model
understanding. No provider, model network request or model acceptance is created.

## Events and independent evidence

The owner creates INTENT_ACCEPTED, USER_CONSTRAINT, PROPOSAL_VALIDATED,
TARGET_ACCEPTED, TARGET_RENDERED, INTENT_COMPLETED, OUTCOME_UNKNOWN and checkpoint
phase events from its actual operations. Every event is signed under a separate
context domain using the existing native owner key, has a scoped monotone
sequence, original request/argument digest, constraints, revision, previous
stream digest and privacy epoch. The completion and durable outbox are committed
in the same existing SQLite transaction. The materialised event projection can
be repaired from that authoritative outbox without calling a target again.

The independent PAN546 reader resolves its issued candidate and actual native
before/after view. Its proof is PREVIEW_VALIDATED, not DOM render or profile
persistence. PAN597 proofs bind its original command, authenticated principal,
actual target connection/generation, object/revision, native source read and
render acknowledgement. DOCUMENT_ACCEPTED is not DOCUMENT_RENDERED. A native
DOMACK retains clientReportedDomCommit and physicalPixelSightCertified:false;
actual browser screenshots are a separate observation, not a signature claim.

Projection proof resolution checks the separately issued native register,
original task and argument bytes, scope, resource, target and signed completion
result. EXECUTOR labels, foreign existing proof IDs, a changed reference's bytes,
or jointly altered caller bytes/hashes cannot mint evidence or execution rights.
Historical unregistered rows are minimised UNKNOWN, not retroactively qualified.

Recovery consumes the retained original commands and signed target register.
A completed native target can reconcile its interrupted invocation once. Mere
acceptance without native target completion remains UNKNOWN after restart. It
never reconstructs an executable old admission/lease or redispatches a target.

## Snapshot, purpose, resources and privacy

The immutable snapshot binds source owner, projector version, authenticated
principal, audience/purpose, privacy/provider epoch, active no-send constraints,
actual task states, event streamhead and every included sequence. There are no
invented omissions: all scoped sequences are represented, with redacted
metadata where privacy has retired the content. The request binds the exact
snapshot bytes/digest, payload bytes/digest and prompt bytes/digest. Hashes alone
are not authority; the owner independently retains and seals the actual bytes.

MAIN_CONTRACT receives the permitted operative references; SPECIALIST_PREVIEW
receives its own minimised purpose/audience and no full Main object resources.
There is no raw final-text, admission-token or audio export. Tests use exclusively
own local synthetic fixtures; non-synthetic sampling needs separate consent.

Main's readset is object/location/access; unrelated card size/view changes do
not invalidate it. Specialists have their own view/access set. A location,
object or rights correction increments only the referenced projection resource
and blocks affected old plans. The local structured correction is a user
constraint, not an ERP fact or a rights grant. Native object/host revision and
actual access scope are also re-read before request/result consumption.

Snapshots are bounded to 65536 UTF-8 bytes; prompt/asset ingress remains 131072.
Task capacity remains128 and owner event capacity4096. An exceeded bound denies
rather than removing no-send or UNKNOWN to fit. Request retention ends at the
existing native lease, at most60000ms. Client cached bytes expire at that same
boundary; the owner purges expired projection caches when preparing a successor.
Completed metadata/own audit is distinct from reusable live request content.

Privacy revoke increments the existing owner projection privacy/session epoch,
revokes affected in-flight checkpoint tasks and clears their caches. Late
responses are generation-fenced and cannot restore DOM/focus/prompt bytes. An
explicit new local contract session creates no model provider and cannot revive
old snapshot content. Historical audit requires the caller's own current
native read capability; another principal cannot access it. Local stop is not
remote rollback and does not claim to undo accepted foreign effects.
